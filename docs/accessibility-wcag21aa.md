# Доступність: WCAG 2.1 AA

**Вимога:** усі сторінки платформи та весь навчальний зміст відповідають WCAG 2.1 рівня AA.

## Що перевіряється автоматично

`tests/a11y/check.mjs` (Playwright + axe-core, правила `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`) на сторінках: вхід, перевірка сертифіката, публічна сторінка бейджа, курс, сторінка матеріалу, тест, анкета, сертифікат, «Мої бейджі». Додатково ловить вікна з помилками та помилки JavaScript.

Останній прогін (локально, Moodle 4.5.15+, тема Boost): **0 автоматично виявлених порушень** на 9 сторінках.

> Автоматичні інструменти виявляють лише частину проблем. Відповідність WCAG 2.1 AA можна заявляти лише після ручного аудиту нижче.

## Ручний чекліст (виконати перед запуском)

### Платформа
- [ ] Увесь шлях слухача (реєстрація → курс → тест → анкета → сертифікат) проходиться **лише з клавіатури**.
- [ ] Фокус завжди видимий; порядок фокусу логічний.
- [ ] Зчитувач екрана (NVDA + Firefox/Chrome; VoiceOver + Safari) коректно озвучує заголовки, кнопки, стан «Виконано», повідомлення про обмеження доступу.
- [ ] Масштаб 200% і ширина 320 px (reflow) — без горизонтальної прокрутки й втрати змісту.
- [ ] Ліміт часу в тесті **вимкнено** (налаштовано), тож WCAG 2.2.1 не порушується.

### Зміст (відповідальність авторів)
- [ ] **Відео:** синхронні субтитри українською (WCAG 1.2.2) + текстова версія (1.2.3). У `course.json` — поля `captions_url` і `transcript_html`.
- [ ] **Аудіодескрипція** або текстова версія, що описує важливу візуальну інформацію відео (1.2.5).
- [ ] **PDF-посібники:** тегований PDF, мова документа «uk», заголовки, альтернативний текст зображень, логічний порядок читання.
- [ ] **Зображення** на сторінках — змістовний `alt`, декоративні — порожній `alt=""`.
- [ ] **Заголовки** у змісті — `<h3>` і нижче (h1/h2 використовує Moodle).
- [ ] Посилання зрозумілі без контексту (не «тут», «детальніше»).
- [ ] Контраст тексту в презентаціях і зображеннях ≥ 4.5:1.

### PDF-сертифікат
PDF, який генерує `mod_customcert` (TCPDF), **не є тегованим** документом. Тому основним доступним способом підтвердження є **HTML-сторінка перевірки** та **бейдж** (обидва пройшли автоматичний аудит). Це варто прямо зазначити в заяві про доступність.

## Заява про доступність

Перед запуском опублікувати сторінку «Доступність» з рівнем відповідності, відомими обмеженнями (наприклад, PDF-сертифікат) і контактом для звернень.
