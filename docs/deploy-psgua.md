# Розгортання на psgua.com

Статус: 🔵 **заплановано**. Нижче — що потрібно з'ясувати в хостинг-провайдера і покроковий план.

## 0. Що вже відомо про хостинг (adm.tools, діагностика 9.11.2026)

| Параметр | Стан |
|---|---|
| SSH, cron, git, вихідні з'єднання (github.com, download.moodle.org) | ✅ є |
| PHP у консолі за замовчуванням | ⚠️ 5.6 — **у консолі завжди використовувати `php8.3`** |
| PHP 8.3.36: intl, mbstring, mysqli, zip, gd, curl, sodium, soap | ✅ є; `opcache` — вмикається для сайту в панелі |
| `max_input_vars` | ❌ 1000 → для academy.psgua.com виставити 5000 у «Налаштування PHP (php.ini)» |
| База даних | MySQL/MariaDB (PostgreSQL немає). **Версія сервера бази — TODO** (потрібно MySQL 8.0+ або MariaDB 10.6.7+) |
| DNS psgua.com | Squarespace; A-запис `academy → 185.104.45.38` додано |

Наш код перевірено і на PostgreSQL 16, і на **MariaDB 10.11** (`--dbtype=mariadb`): усі перевірки наскрізного тесту пройдено.


## 1. Питання до хостингу (потрібні відповіді перед стартом)

| # | Питання | Чому важливо |
|---|---|---|
| 1 | Тип хостингу: VPS / виділений сервер чи **спільний (shared) хостинг**? Чи є SSH-доступ? | Moodle потребує CLI (`php admin/cli/...`), cron щохвилини та теку даних поза веб-коренем. На більшості shared-хостингів це обмежено |
| 2 | Версія PHP: **8.1, 8.2 або 8.3**? | Вимога Moodle 4.5 |
| 3 | Розширення PHP: `pgsql` або `mysqli`, `intl`, `mbstring`, `xml`, `zip`, `gd`, `curl`, `sodium`, `soap`, `opcache` | Обов'язкові/рекомендовані для Moodle |
| 4 | `max_input_vars` ≥ **5000** (php.ini) | Обов'язково для Moodle 4.5 |
| 5 | База даних: PostgreSQL 13+ (рекомендовано) або MariaDB 10.6+ / MySQL 8.0+ | Вимога Moodle 4.5 |
| 6 | Домен платформи — **academy.psgua.com** (створено в панелі adm.tools) і HTTPS-сертифікат (Let's Encrypt) | Посилання на сертифікати й бейджі мають бути стабільними й захищеними |
| 7 | Cron щохвилини: `php admin/cli/cron.php` | Завершення курсів, видача бейджів, листи |
| 8 | SMTP для листів (напр. `noreply@psgua.com`; контакт видавця бейджів — `info@uaguides.com`) | Сповіщення, відновлення пароля, бейджі |
| 9 | Резервне копіювання (база + `moodledata`) щодня | Захист даних слухачів і виданих сертифікатів |
| 10 | Доступ сервера до `download.moodle.org` | Встановлення українського мовного пакета |

> ⚠️ **Стабільність адреси критична:** посилання на перевірку сертифікатів і бейджів містять домен. Змінювати домен після видачі перших сертифікатів не можна.

## 2. Рекомендовані ресурси (для старту до ~500 активних слухачів)

Орієнтовно: 2 vCPU, 4 ГБ RAM, 40 ГБ диска + місце під відео. **Відео краще не зберігати в Moodle**, а розміщувати на окремому сервісі (наприклад, YouTube/Vimeo з субтитрами або окреме сховище). Цифри — орієнтир, не результат навантажувального тестування.

## 3. Діагностика

У SSH-консолі хостингу (adm.tools → сайт → SSH):

```bash
bash scripts/check-server.sh
```

## 4. Покроковий план

```bash
scripts/install-moodle.sh /var/www/moodle
```

1. Створити базу даних і користувача.
2. Створити теку даних поза веб-коренем, напр. `/var/moodledata` (власник — користувач вебсервера).
3. Встановити Moodle: веб-майстер `https://academy.psgua.com/install.php` або `admin/cli/install.php`.
4. Застосувати налаштування й зібрати курси:

```bash
php8.3 -d max_input_vars=5000 provisioning/provision.php --moodle=/var/www/moodle
```

5. Налаштувати cron (`php8.3 /шлях/до/moodle/admin/cli/cron.php` щохвилини), SMTP (`Адміністрування > Сервер > Електронна пошта`), `noreplyaddress`.
6. Перевірити: `Адміністрування > Сповіщення` (без помилок), `Звіти > Перевірки безпеки`.
7. Прогнати наскрізний тест на **тестовій копії** (staging), не на робочому сайті.
8. Прогнати `tests/a11y` і ручний чекліст доступності.

## 5. Що лишається вирішити Асоціації

- Домен `academy.psgua.com` після видачі перших сертифікатів не змінювати.
- Політика конфіденційності та обробки персональних даних (Moodle має інструмент `tool_dataprivacy`).
- Хто адмініструє платформу (оновлення безпеки Moodle виходять щомісяця).
